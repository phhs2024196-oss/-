# AI 부업/사업 아이디어 저장소

사용자가 던지는 AI 부업·사업 아이템을 구조화해서 저장하고, 필요할 때 꺼내 보고, 명령하면 저장된 아이디어들의 **장점만 뽑아 융합한 새 아이디어**를 생성하는 저장소.

## 폴더 구조

```
ideas/                 사용자가 제공한 (또는 검증된) 사업 아이디어 원본
  INDEX.md             사람이 보는 목록 (표)
  ideas.json           기계 판독용 인덱스 — 융합 생성 시 이 파일의 strengths를 재료로 사용
  NNN-슬러그.md         아이디어 1건당 파일 1개

fusions/                ideas/의 강점을 조합해 새로 생성한 아이디어
  INDEX.md              사람이 보는 목록
  NNN-슬러그.md          융합 아이디어 1건당 파일 1개 (출처 아이디어·강점 번호 명시)

research/               특정 아이디어를 뒷받침하는 근거 자료 (설문·리포트·인터뷰 등)
```

## 아이디어 파일 포맷 (`ideas/NNN-슬러그.md`)

모든 아이디어는 아래 항목을 반드시 포함한다. 특히 **"핵심 강점"** 섹션은 나중에 융합(fusion) 생성 시 재료로 직접 인용되므로, 애매하게 쓰지 않고 "무엇이 왜 강점인지"를 한 문장씩 구체적으로 쓴다.

```markdown
# [ID] 제목
- 수익모델(MODEL) / 타겟(TARGET) / 상태 / 등록일 / 출처 / 근거신뢰도(v2 데이터인 경우)
## 한 줄 요약
## 핵심 강점 (Fusion 재료 — 일반)      ← S1, S2... — 남들도 할 수 있는 강점
## 경쟁우위 / 모방장벽 (Fusion 재료 — 우선)  ← M1, M2... — v2 MOAT 필드가 있을 때만. 융합 시 M번호를 S번호보다 우선 채택
## 상세 설명   (CORE·NUM·SKILL·HOWTO)
## 리스크/약점 (CONS·UNCERTAIN)
## 관련 자료
```

MODEL/TARGET이 없는 구버전(v1) 아이디어는 카테고리·상태·등록일·출처만 유지하고, "경쟁우위/모방장벽" 섹션도 생략한다(001~027 해당).

## 입력 데이터 포맷 (태그형)

사용자가 아래 태그 형식으로 원본 데이터를 붙여넣으면, 각 태그를 저장 포맷의 아래 섹션으로 자동 매핑해서 `ideas/NNN-슬러그.md`로 저장한다.

```
TITLE::제목 (원본 출처명 포함 가능, 예: 유튜브 채널명)
TOPIC::주제/카테고리
CORE::핵심 구조적 사실 (세미콜론으로 구분)
NUM::수치 근거 (세미콜론으로 구분)
INSIGHT::시사점 (세미콜론으로 구분)
HOWTO::실행 방법 (세미콜론으로 구분)
UNCERTAIN::미검증/불확실 사항
```

매핑 규칙:
- `TITLE`/`TOPIC` → 제목·카테고리·출처
- `CORE` → "핵심 요소" (상세 설명 내)
- `NUM` → "수치 근거" (상세 설명 내, research 성격)
- `INSIGHT` → **강점 후보로 우선 검토**. 이 중 사업적 이점("~을 할 수 있다", "~가 낮다/크다")에 해당하는 항목만 "핵심 강점(S1, S2…)"으로 승격하고, 종속·리스크 성격("~에 의존적이다" 등)은 "리스크/약점"으로 분류한다 — 자동으로 다 강점 취급하지 않음
- `HOWTO` → "실행 방법"
- `UNCERTAIN` → "리스크/약점"에 `[미검증]` 표시로 포함

## 입력 데이터 포맷 (태그형 v2 — 현재 권장 포맷)

028부터 적용 중인 확장판. v1/v1.1과의 차이는 **강점의 종류를 미리 분리**해서 준다는 점 — 이러면 제가 "이게 진짜 강점인지 그냥 업계 표준인지" 판단할 필요가 없어져서 더 정확하다.

```
TITLE::제목|채널명
MODEL::수익모델 유형 (B2B-SaaS / B2C-구독 / B2C-단건판매 / 광고형 / 대행-외주형 / 노동-시급형 / 커머스형, 복수 가능)
TARGET::타겟 고객/시장
CORE::핵심 메커니즘 (세미콜론 구분)
NUM::초기자본;소요시간;예상수익 범위
SOURCE_RELIABILITY::(a)크리에이터 본인 실적 공개 / (b)크리에이터의 일반적 추정 / (c)제3자 통계 인용
PROS::일반 강점 (세미콜론 구분) — 남들도 따라할 수 있는 강점
MOAT::경쟁우위/모방장벽 — 시간이 지나도 남이 못 따라하는 이유. 없으면 "명시적 모방장벽 없음"
CONS::리스크/약점 (세미콜론 구분)
SKILL::요구 기술 난이도(없음/낮음/중간/높음) + 구체 툴
HOWTO::실행 단계 (화살표 → 구분)
UNCERTAIN::불확실/미검증 사항
```

매핑 규칙:
- `MODEL`/`TARGET` → 파일 상단 메타데이터
- `PROS` → "핵심 강점 (일반)" S1, S2...로 그대로 승격 (v1의 INSIGHT 재분류 작업 불필요)
- `MOAT` → "경쟁우위/모방장벽" M1, M2...로 별도 섹션 — **융합 시 S보다 M을 우선 채택**
- `SKILL`/`CORE`/`NUM`/`HOWTO` → "상세 설명"
- `CONS`/`UNCERTAIN` → "리스크/약점" (UNCERTAIN은 `[미검증]` 표시)
- `SOURCE_RELIABILITY` → 파일 상단 메타데이터에 명시, (b)/(c)인 경우 NUM의 수치를 "추정치"로 취급

## 입력 데이터 포맷 (카탈로그 일괄형)

여러 아이템을 표 형식(아이템/핵심 방식/초기자본/자동화율/판정 등급)으로 한번에 제공하는 경우:

1. 표 전체를 원본 그대로 `research/catalog-{날짜}-{건수}.md`에 보존 (근거자료로서 모든 등급 유지)
2. 그중 **등급 A / A(조건부)**로 표시된 항목만 `ideas/NNN-슬러그.md`로 승격, "핵심 강점" 추출
3. B/C/D/제외 등급은 카탈로그 원본에만 남고 개별 승격하지 않음 — "OO 아이템도 승격해줘"라고 하면 그때 개별 추가

## 사용 방법 (명령어)

| 사용자가 이렇게 말하면 | 하는 일 |
|---|---|
| "이 아이디어 저장해줘" + 내용 | `ideas/`에 새 번호로 파일 생성, "핵심 강점" 추출해서 명시, `ideas.json`·`INDEX.md` 갱신 |
| "저장된 아이디어 보여줘 / 목록" | `ideas/INDEX.md` 기준으로 요약 제시 |
| "OO 아이디어 꺼내줘" | 해당 `ideas/NNN-*.md` 전체 내용 제시 |
| "장점만 합쳐서 새 아이디어 만들어줘 / 융합해줘" | `ideas.json`의 강점(S번호)들을 골라 조합 → 새 아이디어를 `fusions/NNN-슬러그.md`로 생성, 어떤 아이디어의 어떤 강점을 가져왔는지 명시, `fusions/INDEX.md` 갱신 |
| "OO 아이디어랑 XX 아이디어만 합쳐줘" | 지정된 두 개(또는 그 이상)의 아이디어에서만 강점을 뽑아 융합 |

융합 아이디어를 만들 때 원칙:
1. **약점은 가져오지 않는다** — 각 원본의 리스크/약점 섹션은 참고만 하고 복제하지 않는다.
2. **강점의 출처를 반드시 표시한다** — 예: "S2(001의 대행료→구독료 전환) + S3(003의 커뮤니티 바이럴 루프)를 결합".
3. **융합 결과도 다시 저장소의 재료가 된다** — 융합 아이디어에도 "핵심 강점" 섹션을 부여해서, 다음 융합에 다시 쓰일 수 있게 한다.
