# AI 부업/사업 아이디어 저장소

사용자가 던지는 AI 부업·사업 아이템을 구조화해서 저장하고, 필요할 때 꺼내 보고, 명령하면 저장된 아이디어들의 **장점만 뽑아 융합한 새 아이디어**를 생성하는 저장소.

## 폴더 구조

```
ideas/                 사용자가 제공한 (또는 검증된) 사업 아이디어 원본
  INDEX.md             사람이 보는 목록 (표)
  ideas.json           기계 판독용 인덱스 — 융합 생성 시 이 파일의 strengths를 재료로 사용
  NNN-슬러그.md         아이디어 1건당 파일 1개

fusions/                ideas/의 강점을 조합해 새로 생성한 아이디어
  INDEX.md              사람이 보는 목록
  NNN-슬러그.md          융합 아이디어 1건당 파일 1개 (출처 아이디어·강점 번호 명시)

research/               특정 아이디어를 뒷받침하는 근거 자료 (설문·리포트·인터뷰 등)
```

## 아이디어 파일 포맷 (`ideas/NNN-슬러그.md`)

모든 아이디어는 아래 항목을 반드시 포함한다. 특히 **"핵심 강점"** 섹션은 나중에 융합(fusion) 생성 시 재료로 직접 인용되므로, 애매하게 쓰지 않고 "무엇이 왜 강점인지"를 한 문장씩 구체적으로 쓴다.

```markdown
# [ID] 제목
- 카테고리 / 상태 / 등록일 / 출처
## 한 줄 요약
## 핵심 강점 (Fusion 재료)     ← S1, S2... 번호 부여, 융합 재료 단위
## 상세 설명
## 리스크/약점
## 관련 자료
```

## 사용 방법 (명령어)

| 사용자가 이렇게 말하면 | 하는 일 |
|---|---|
| "이 아이디어 저장해줘" + 내용 | `ideas/`에 새 번호로 파일 생성, "핵심 강점" 추출해서 명시, `ideas.json`·`INDEX.md` 갱신 |
| "저장된 아이디어 보여줘 / 목록" | `ideas/INDEX.md` 기준으로 요약 제시 |
| "OO 아이디어 꺼내줘" | 해당 `ideas/NNN-*.md` 전체 내용 제시 |
| "장점만 합쳐서 새 아이디어 만들어줘 / 융합해줘" | `ideas.json`의 강점(S번호)들을 골라 조합 → 새 아이디어를 `fusions/NNN-슬러그.md`로 생성, 어떤 아이디어의 어떤 강점을 가져왔는지 명시, `fusions/INDEX.md` 갱신 |
| "OO 아이디어랑 XX 아이디어만 합쳐줘" | 지정된 두 개(또는 그 이상)의 아이디어에서만 강점을 뽑아 융합 |

융합 아이디어를 만들 때 원칙:
1. **약점은 가져오지 않는다** — 각 원본의 리스크/약점 섹션은 참고만 하고 복제하지 않는다.
2. **강점의 출처를 반드시 표시한다** — 예: "S2(001의 대행료→구독료 전환) + S3(003의 커뮤니티 바이럴 루프)를 결합".
3. **융합 결과도 다시 저장소의 재료가 된다** — 융합 아이디어에도 "핵심 강점" 섹션을 부여해서, 다음 융합에 다시 쓰일 수 있게 한다.
