### ① 문항팀 "만든다"
| 역할 | 담당 | 입력 → 출력 | 모델 | 통과 조건 |
|---|---|---|---|---|
| 출제자 | 신규 문항 창작 | 출제계획표 → 문항 YAML | **Opus** | 자체 검산 첨부 |
| 검산자 | 정답·조건을 sympy로 재계산 | YAML → PASS/FAIL | Sonnet | PASS |
| 블라인드 풀이자 | 정답 안 보고 풀어 일치·난이도 확인 | 발문만 → 답·난이도·소요시간 | Sonnet | 답 일치 |
| 해설 작가 | 학교가 원하는 풀이 방향으로 해설 + 단계별 채점기준 | 확정 문항 → 해설·채점기준 | Sonnet | 검산자 재확인 |

|---|---|---|---|---|

|---|---|---|---|---|

## 4. 운영 규칙
- **팀 = 상시 스레드 1개.** 지금 여는 건 ①②③④ 4개. ⑤는 2027-05, ⑥은 MVP 착수 때.
- **동시 서브에이전트 팀당 4개 이하.**
- **인계는 파일로.** `/mnt/project-files/handoff/<교재명>/` 아래 패키지(YAML·그림 스펙·체크리스트)를 두고 다음 팀이 읽는다.
- **게이트 4개만 기억하면 됨:** A 문항 확정(검산 PASS + 블라인드 일치) → B 품질보증 통과 → C 대표 승인 → D 채점 일치율 90%.
- **토큰 절약:** 결과는 FAIL 줄만, 교차검증은 불일치 시만, PDF는 pdftotext 우선.
