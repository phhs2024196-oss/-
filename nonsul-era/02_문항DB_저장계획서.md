# 논술의 시대 — 문항 DB 저장계획서 v2.0

작성 2026-11-20 · 대상: 수리논술 15개교 교재(약 4,135문항, 사업계획서 v2.1) + 기출 DB(600~800문항) + AI 첨삭

> 한 줄 요약: **문항 1개 = YAML 파일 1개(양식 v2)**를 git에 원본으로 두고, 검사기(`validate.py`)를 통과한 것만 SQLite DB와 교환용 JSONL로 빌드한다. DB는 언제든 다시 만들 수 있는 파생물이다. 2027년 여름 사이트 개발 때 같은 스키마를 Postgres로 옮긴다.

이 문서의 도구는 실제로 만들어 기존 300문항으로 시험했다(§10). 도구 위치: `nonsul-era/db/`, `nonsul-era/tools/`.

---

## 1. 설계 원칙

| # | 원칙 | 이유 |
|---|---|---|
| 1 | 원본은 사람이 읽을 수 있는 텍스트(문항당 YAML, 수식은 `|` 블록에 역슬래시 그대로) | Claude Code가 직접 읽고 고칠 수 있고, git으로 모든 수정 이력이 남는다. 노션·구글시트는 LaTeX·버전관리·대량 자동수정에 약하다 |
| 2 | 문항 단위 저장, 교재는 "배치표"로 분리 | 같은 기출이 기생기사(기출 해설)와 유유상종(유형별 N제)의 예제처럼 여러 교재에 실릴 수 있고, 개정판·재수록도 생긴다(v2.1 계획 수록 4,135). 문항을 복사하면 오류 수정이 한쪽에만 반영된다 |
| 3 | ID는 한 번 부여하면 영구 | 정오표·오류 신고·AI 첨삭 기록이 모두 ID를 참조한다. 폐기해도 번호를 재사용하지 않는다 |
| 4 | 기계가 검사할 수 있는 것은 전부 기계가 검사 | 배점 합, 소문항 소계, ID 형식, 분류값, 수식 표기, 범위 밖 도구는 `validate.py`가, 정답은 sympy 검산 스크립트가 확인한다. 사람은 기계가 못 보는 것(문항의 질, 논리 비약)만 본다 |
| 5 | 판매 가능 여부는 상태값 하나로 결정 | `status ≥ verified`가 아니면 교재 조판에 못 들어간다 |
| 6 | 기출 원문은 내부 분석용으로만 저장, 교재·사이트 노출은 허락 후 | 일부 대학 자료에 상업적 사용 금지 표기가 있다. `source.allowed_use ≠ full_reproduction`인 문항은 조판·공개 JSONL에서 원문 대신 출처 ID와 자체 해설만 나간다 |
| 7 | 개인정보는 문항 DB에 넣지 않음 | 학생 답안·약점 데이터는 AI 첨삭용 별도 DB(사이트 단계)에 둔다 |

## 2. 저장 구조와 단계별 진화

| 단계 | 시기 | 원본 | 조회·집계 | 백업 |
|---|---|---|---|---|
| ① 제작기 | 2026-12 ~ 2027-07 | git 저장소의 md 파일 | `build_db.py` → SQLite(`build/nonsul.db`) | GitHub 비공개 저장소 + 주 1회 압축본을 구글 드라이브 |
| ② 사이트기 | 2027-08 ~ | 동일(md가 계속 원본) | SQLite → Postgres(Supabase 등) 단방향 동기화. 사이트는 읽기 전용 | 위 + DB 자동 백업 |
| ③ 확장기 | 2028 ~ | 동일. 약술형·인문은 `school`·`types`·`subjects` 값만 추가 | 동일 | 동일 |

왜 처음부터 Postgres/노션이 아닌가: 지금 필요한 것은 "검사 가능한 원본 + 이력"이다. 사이트가 없을 때 서버 DB는 관리 비용만 든다. 스키마(`db/schema.sql`)는 Postgres로 옮길 때 JSON 열을 JSONB로 바꾸는 것 외에는 그대로 쓰도록 짰다.

## 4. ID 체계

| 종류 | 형식 | 예 | 설명 |
|---|---|---|---|
| 자체 제작 | `학교-T유형-순번3` | `SSU-T01-011` | 유형 안 일련번호. 교재 순서와 무관 |
| 기출 변형 | 자체와 같음 + `parent` | `DGU-T09-014` (parent: `DGU-G25-02`) | 원 기출을 `parent`로 연결 |
| 실전 기출 | `학교-G연도2[회차]-번호2` | `SSU-G26-04`, `SJU-G26A-01` | G=실전, 연도는 학년도. 세종 A/B형·오전/오후는 회차 글자 |
| 모의논술 | `학교-M연도2[회차]-번호2` | `DGU-M27-02` | M=대학 공식 모의 |
| 공통 교재 | `COM-T유형-순번3` | `COM-T03-120` | 학교 무관 공통 교재 |

학교 코드(영문 2~4자): SSU 숭실, DGU 동국, SJU 세종, YSU 연세, KU 고려, SGU 서강, SKKU 성균관, HYU 한양, CAU 중앙, KHU 경희, EWHA 이화, KKU 건국, UOS 서울시립, HIU 홍익, COM 공통. (나머지는 15개교 확정 때 `taxonomy.yaml`에 추가)

기존 300문항은 `S01-01 → SSU-T01-001`, `D → DGU`, `J → SJU`로 바꾸고 옛 ID는 `legacy_id`에 남긴다.

교재 코드: `학교-시리즈-시즌` 예) `SSU-YUYU-2028`(숭실 유유상종 2028 시즌), `COM-JCTM-2028`(절차탁마). 시리즈 약어는 교재 기획 때 `books/`에 정한다.

## 5. 문항 파일 형식 — 양식 v2 (2026-11-20 개정)

뼈대는 `db/item_template.yaml`(그대로 검사기를 통과하는 완성 예시). 값 목록은 `db/taxonomy.yaml`.

**v2 개정 경위**: 「통합 문항 입력 양식 v1.0」 제안서(한국 대학 문항카드 + IB·Edexcel 마크스킴 + TIMSS 진단코드 + Eedi 오개념 카탈로그 + 1EdTech CASE 관계)를 검토해 아래처럼 반영했다.

| 제안 | 반영 | 이유 |
|---|---|---|
| 채점표 1마크 = 1행(M·A·B·R·C, depends_on, ft, evidence, accept, cao, not_penalized, implied_ok) | **채택** | AI 첨삭이 기계적으로 적용 가능. 이월(FT)·의존 규칙을 필드로 검사 |
| 해설 A(방향)·B(전 과정)·ALT(대체 풀이) + 단계↔마크 연결 + 힌트 사다리 | **채택** | AI 피드백이 "어느 단계에서 끊겼는지" 지목 |
| 전역 오개념 카탈로그 + 문항별 연결, 결과 코드 70~78·79·90·99 | **채택** | 학생별 오개념 누적 통계·처방 |
| 처방 링크(trigger·relation·target=개념/문항), 교재 번호는 배치표에서 렌더링 | **채택** | 판 갱신 시 링크 유지(교재 배치는 v1부터 books/ 로 분리) |
| 출처·허락(license·permission_status·allowed_use·derivative_level) + 내보내기 차단 | **채택** | 원문 전재는 허락 시에만(판례: 서울지법 97노50 — 입시문제는 저작물) |
| 검수 이력(stage·actor·prompt_version·verdict·reason_codes·restart_from·computed_answers) | **채택** | 재시작 지점·프롬프트 변경 영향 추적 |
| 교육과정(version 2015/2022, 성취기준 verified, 행동영역, 단원 경로), exam_family·item_type·origin | **채택** | 2015/2022 혼재, 약술·인문·자격증 확장 |
| 3층 중복 탐지(정규화 해시 / 숫자·변수 마스킹 MinHash / 발상 태그) | **채택** — 빌드 때 자동 계산(원본 파일에 쓰지 않음) | 4,135문항 규모에서 수작업 중복 확인 불가 |
| grading_runs·item_stats(판독/채점 분리, n회 독립 채점) | **채택** — 스키마만, 사이트 단계에서 사용 | 판독 실패가 채점 오류의 대부분이라는 연구 결과 반영 |
| JSONL 1줄 = 1문항을 **원본**으로 | **변경**: 원본은 문항당 YAML, JSONL 은 빌드 산출물(교환 표준) | 한 줄 JSON 은 LaTeX 역슬래시 이중 표기(`\\frac`)·diff 불가로 사람·Claude Code 편집에 취약. 제안서도 JSONL 을 "교환 표준"으로 규정 |
| item_id(ULID) + item_code 분리 | **보류** | git 파일명 ID 가 이미 영구 키. 학교-유형-순번 코드 유지 |
| 상태값(composed·generated·approved·rejected) | **대응만**: compose·generate 는 검수 이력 단계로, approved = verified | 기존 상태 흐름·검사기 유지 |
| 마크 1~3점 권장 | **조정**: 대학 원배점(숭실 25, 동국 8·10·12, 세종 80·90·100)을 그대로 쓰고 마크도 그 단위 | 교재가 실전 배점을 재현해야 함 |

**구조 요약**

```
문항: id · version · status · exam_family · item_type · origin · school · type · variant_of · replaces
      level · form · points · time_estimate_min · intent · key_idea · stuck · idea_tags · tags
      curriculum{version, subjects, scope_2028, scope_confirmed, standards[], content_area, behavior_domain, unit_path, key_concepts}
      difficulty{rater, p_value, n} · source{rights_holder, license, permission_status, allowed_use, derivative_level, 기출이면 institution·admission_year·question_no·official_url …}
      verify · stimuli[] · stem
      subparts[]: id · stem · points · depends_on · answer{kind, value, equivalents, tolerance}
                  solutions[]: id · audience(A·B·ALT) · method_no · key_idea · steps[]{id, content, criteria[]} · hint_ladder
                  rubric: rules{ft_scope, ft_requires_working, a_requires_m, misread_penalty, isw}
                          criteria[]: id(1.M1) · mark_type · points · evidence · depends_on · implied_ok · ft{allowed, from, max_points, condition} · accept · cao · not_penalized · steps
                          deductions[]: code · condition · effect(minus·cap·zero) · value
                  outcome_codes[] · misconceptions[]: id(카탈로그) · outcome_code(70~78) · wrong_work · detect_cue · feedback · remedy[]
      remedy_links[]: id · trigger{type, ref} · relation · target{kind: concept|item, ref} · priority
      reviews[] (덧붙이기만) · created · updated
```

**필수 수준**: 구조·배점·참조·수식·저작권 규칙은 항상 오류. v2 완비 항목(마크 종류, 해설 A·B, 오개념 ≥1, 처방 ≥1, 출제의도, 발상 태그, 행동영역, 범위 확정)은 `draft`~`r2_pass`에서는 경고(GATE), **`verified` 이상이면 오류**. 그래서 이관 문항은 지금 draft로 존재하되 판매 전에 반드시 v2로 채워진다.

**작성 규칙**: 글이 들어가는 값은 블록(줄바꿈) 형식, 여러 줄이면 `|` 블록. `{}`·`[]` 안에 쉼표·물음표가 든 글을 넣으면 YAML이 깨진다(검사기가 "YAML 파싱 실패"로 알림). 수식은 인라인 `$...$`, 별행 `$$...$$`, `$` 안쪽 공백·`\(`·`\[`·`\tag` 금지.

**내보내기 차단**: `allowed_use ≠ full_reproduction`이면 공개 JSONL(`items_public.jsonl`)과 교재 조판(`validate --book`)에서 제외·오류. `full_reproduction`은 `permission_status`가 `granted`(허락서 `permission_ref` 필수) 또는 `not_needed`(자체 문항)일 때만 허용.

## 6. 2028 출제범위 태그 (가장 중요한 분류)

2028학년도부터 2022 개정 교육과정이 적용되고 수능 수학은 대수·미적분Ⅰ·확률과통계만 본다. 대학별 논술 범위는 아직 다 확정되지 않았다(대학별 2028 시행계획·요강으로 확인 필요). 그래서 모든 문항에 "이 문항을 풀려면 어디까지 배워야 하나"를 태그한다.

| 태그 | 뜻(2022 개정 기준) | 2015 개정으로 보면 |
|---|---|---|
| `common` | 대수·미적분Ⅰ·확률과통계만으로 풀림 | 수학·수Ⅰ·수Ⅱ·확통 |
| `calc2` | 미적분Ⅱ 필요 | 미적분(초월함수 미분, 치환·부분적분, 수열의 극한·급수, 덧셈정리, 매개변수·음함수 등) |
| `geom` | 기하 필요 | 기하(벡터, 이차곡선, 공간도형) |
| `unknown` | 미태깅 | |

과목 대응(수학Ⅰ≈대수, 수학Ⅱ≈미적분Ⅰ, 미적분≈미적분Ⅱ)은 큰 틀이며, 세부 단원 이동(예: 수학적 귀납법의 위치)은 2022 개정 교육과정 원문으로 한 번 확인해야 한다(불확실).

## 7. 상태와 검수 흐름

```
draft ─r1─▶ r1_pass ─r2(독립 2회)─▶ r2_pass ─sympy+게이트─▶ verified ─(5% 표본)─▶ sampled
                                                               └────────────▶ published(교재 수록)
 1차 탈락: 제작 단계 백지부터 재시작 · 2차 탈락: 풀이과정부터 재작성 · 같은 문항 3회 연속 탈락 시 폐기(retired)
```

| 단계 | 하는 일 | 누가 | 기록(`reviews`) |
|---|---|---|---|
| 구성 | 유형별 설계도(열쇠·막힘·L·형식) 10행 | Fable급 모델 | — |
| 제작 | 문항·모범답안·채점표·검산 스크립트 | Opus급 모델 | — |
| r1 | 출제범위·구상 적합성·형식·중복 | Sonnet급 모델(제작과 다른 세션) | `stage: r1_scope` |
| r2 | **정답을 보지 않고** 문제만 받아 독립 풀이 2회, 두 답(`computed_answers`)이 서로·제작 정답과 일치 | 다른 세션 2개(가능하면 다른 계열 AI 1개 포함) | `stage: r2_calc_1`, `r2_calc_2` |
| verify | `run_verify.sh` PASS + `validate.py` ERROR 0 + 게이트 G1~G7 + v2 완비 | 기계 | `stage: verify` |
| sample | 주간 verified 의 5%(최소 5문항) 본인 검수 | 본인 | `stage: human_sample` |

게이트(기존 N제 제작 지침 승계): G1 sympy 일치 · G2 난이도 분포 L4×2/L5×6/L6×2(10문항 유형 기준) · G3 형식 4종 이상, 같은 형식 3회 이하 · G4 채점표 합 = 배점 · G5 금지목록·기출과 비중복 · G6 마지막 소문항이 앞 결과 사용(동국·세종) · G7 조건만으로 답 유일, 교육과정 안.

표본 검수의 한계(정직하게): 표본에서 오류 0건이어도 95% 신뢰로 보장되는 오류율 상한은 약 3/n이다(파일럿 564문항의 5% = 28개면 약 11%). 그래서 품질 보증의 중심은 표본 검수가 아니라 **sympy 전수 검산 + 독립 재풀이**이고, 표본 검수는 "공정이 망가졌는지" 감시하는 장치로 쓴다. 표본에서 오류 1건이면 그 배치 표본을 15%로 늘리고, 2건 이상이면 배치 전체를 r2부터 다시 돌린다. 검토 모델은 "오류를 일부러 심은 문항 20개"로 먼저 시험해 18개 이상 잡는 설정만 쓴다.

## 8. 기출 DB와 저작권

- 원본 PDF는 `sources/<학교>/` 에 읽기 전용 보관(파일명: `SSU_2026_실전.pdf`), 문항 파일은 `items/<학교>/PAST/`.
- 기출 문항 파일에는 원문(제시문·논제)을 **내부 분석용으로** 옮겨 적고, 모범답안·채점표·대표 오답은 자체 작성한다. 대학이 공개한 채점 기준은 `## 메모`에 출처와 함께 요약한다.
- 교재 조판·사이트 노출 규칙: `permission_status: granted`(허락서 `permission_ref`)이고 `allowed_use: full_reproduction`일 때만 원문을 싣는다. 아니면 "숭실대 2026학년도 4번" 같은 출처 표기 + 자체 해설만 싣는다(조판 도구가 이 값을 보고 자동으로 가림).
- 기출 변형은 숫자만 바꾸는 수준 금지(기존 지침 G5). `parent`로 원 기출을 연결해 "이 기출의 어떤 열쇠를 연습시키는 문항인가"를 남긴다.
- 대학 입학처 문의 결과는 `sources/<학교>/LICENSE.md`에 날짜와 함께 기록한다.

## 9. 교재 배치·버전·정오표

- `books/<교재코드>.yaml`: 교재명, 시리즈, 학교, 시즌, 판, 문항 목록(ID·장·순서). 조판 도구는 이 파일만 보고 PDF를 만든다.
- 출고 확정 시 `build_db.py --lock books/<코드>.yaml` → `books/<코드>.lock.yaml`(문항 ID·version·파일 전체 해시)을 커밋한다.
- 판매 후 문항을 고치면 `version`을 올리고 `reviews`에 `{stage: errata, actor_type: human, actor_id, date, verdict: pass, note}`를 남긴다. 이후 `build_db.py`가 스냅샷과 해시가 다른 문항을 "정오표 대상"으로 출력한다(본문과 정답·배점·소문항 배점·난이도·열쇠 변경만 해당 — status·reviews 같은 관리 필드 변경은 제외. version을 안 올렸으면 경고).
- 오류 신고 원본은 git의 `errata/<날짜>-<ID>.yaml`(item_id, reported, channel, description, severity typo·wording·answer·rubric·scope, fixed_version, status). DB는 매번 재생성되므로 DB에만 두지 않는다. 신고자 개인정보는 저장하지 않는다.

## 11. AI 첨삭과의 연결

- 채점 단위 = `rubric_steps` 한 행. 손글씨 답안을 단계별로 대조해 부분점수를 준다.
- `stuck`(막히는 지점)과 `대표 오답`은 힌트·오답 진단 문구의 근거.
- 학생별 약점 DB는 `concepts`·`form`·`type`으로 집계한다. 학생 데이터 자체는 이 저장소에 두지 않는다.
