# 문항 제작 지침 (모든 제작·검토 작업에 적용)

기존 「유형별 수리논술 N제 공통 제작 지침」(2026-11-16)을 문항 1개 = 파일 1개 형식에 맞게 옮긴 것. 분류값은 `db/taxonomy.yaml`이 기준이다.

## 1. 난이도 L — 막히는 지점 수로 판정 (소재가 어려워 보인다고 올리지 않는다)

| L | 기준 |
|---|---|
| L3 | 수능 쉬운 4점 = 중위권 대학 실전 평균 |
| L4 | 수능 준킬러. 발상 1개로 끝남 |
| L5 | 수능 킬러급. 경우 분류 / 조건 해석 / 2단계 이상 구성 중 하나가 필수 |
| L6 | 보조함수·불변량·귀류 중 하나를 수험생이 스스로 설정(힌트 소문항 없이) |
| L7 | 교육과정 밖 — **금지**(로피탈, 테일러 전개, 편미분, 행렬, 복소평면, 이중적분 등) |

유형 1세트(10문항) 분포: L4 2 → L5 6 → L6 2, 쉬운 것부터 배열. 교재 기획에 따라 다른 분포를 쓰면 `books/*.yaml`에 이유를 적는다.

## 2. 형식 12종 (문항당 1개)

추론 · 분류 · 이중세기 · 최적2단 · 구성 · 점화 · 불변량 · 일반화 · 존재 · 귀류 · 귀납구조 · 전수

한 유형 10문항 안에서 같은 형식 최대 3회, 형식 4종 이상. 함수·도형·수치 설정이 서로 닮지 않게("숫자만 바꾼 문항" 금지).

## 3. 학교별 규격 (2027학년도 기준 — 2028은 요강 확인 후 갱신)

| 학교 | 문항 형태 | 배점 | 범위 |
|---|---|---|---|
| 숭실 SSU | 제시문(교과서 정리 1~2개 + 【출처: 과목 「단원」】) + 논제 1개(필요시 소문항 2개) | 25 | 수학·수Ⅰ·수Ⅱ·미적분 |
| 동국 DGU | 【가】~【다】 제시문 + 소문항. 30점형 (8·10·12), 40점형 (8·10·10·12). "제시문을 인용하여" 서술, 줄 수 제한 표기 | 30 / 40 | 수Ⅰ·수Ⅱ·미적분·확통 (기하 포함 여부 확인 중 — taxonomy note) |
| 세종 SJU | 제시문 없음. 조건 서술 → (1)(2)(3) 직렬, 문항마다 "보이시오" 증명 소문항 1개 이상, (3)은 (1)(2) 결과 사용 | 260(80·90·90) / 270(80·90·100) | 수Ⅰ·수Ⅱ·미적분 |

동국·세종은 소문항이 이어져야 한다(마지막 소문항이 앞 결과 사용). 다른 학교는 그 학교 기출 분석 후 이 표에 행을 추가한다.

**범위 밖 도구 금지**: 모범답안도 그 학교 범위 안의 도구만 쓴다. 예) 세종·숭실 모범답안에서 벡터·내적 사용 금지(기울기 곱 −1, 거리 공식으로 대체). 범위 밖 풀이를 보여주고 싶으면 `## 메모`에 "참고 풀이"로 분리.

## 4. 금지 목록 (소재·열쇠가 겹치면 폐기)

- Σ_{n=1}^{100} d(n) (약수 개수 합 = Σ[100/k], 482)
- 타일링 점화 t_n = t_{n−1} + 2t_{n−2}
- e^x ≥ ax+b 에서 ab의 최댓값
- y = x³−3x 에 그은 접선의 개수 N(a) 분류, x³−3x 를 쓰는 문항 전반
- 등비수열 합을 적분해 π/4(라이프니츠 급수) 또는 ln2 를 얻는 문항
- 피보나치 망원 급수, 주기 수열
- 직선·원 등의 교점 개수 a_n 규칙 찾기
- 주사위 눈으로 이차방정식 판별식 전수 조사
- √2 등 무리수성 귀류 증명
- 조건 (가)(나)(다)로 삼차·사차함수를 결정하는 흔한 꼴(극값·대칭 조건 나열) — 조건의 종류가 새로울 때만 허용
- 각 학교 기출·모의 문항 및 그 숫자 변형(변형은 `kind: variant` + `parent`로만, 열쇠를 바꿀 것)
- 수능·평가원 기출, 유명 경시 문제를 그대로 옮긴 것
- **DB에 이미 있는 문항과 열쇠·설정이 같은 것** — 제작 전 `python3 tools/search.py <단어>`로 열쇠·개념을 검색해 확인

## 5. 문항 파일 작성

- 뼈대: `db/item_template.md`. 경로 `items/<학교>/<유형>/<ID>.md`, 파일명 = ID.
- 새 ID = 그 유형의 마지막 순번 + 1(폐기 번호 재사용 금지).
- 본문 절 순서: 제시문 · 논제 · 모범답안 · 정답 · 채점표 · 대표 오답 · 메모.
- 모범답안 ①②③…은 채점표 단계와 1:1. 소문항이 바뀌어도 번호를 이어 간다(①②③ / ④⑤ / ⑥⑦). 증명은 논리를 빠짐없이.
- 채점표는 4열 `| 단계 | 소문항 | 내용 | 배점 |`. 단일 논제면 소문항 칸에 `-`.
- 수식: 인라인 `$...$`, 별행 `$$...$$`, `$` 안쪽 공백 금지, `\(` `\[` `\tag` `\label` 금지, 표 안 `|` 대신 `\lvert x\rvert`·`\mid`, KaTeX 지원 명령만, 그림 대신 좌표·조건을 글로.
- 한국 교과서 용어·문체("~을 구하시오", "~임을 보이시오").

## 6. 검산 스크립트 `verify/<학교>-<유형>-s<세트>.py`

- 세트(순번 10개 단위: 001~010 = s1, 011~020 = s2 …)마다 파일 하나. `db/verify_template.py`를 복사해 시작한다. 이관 문항(세트 1)은 기존 파일 `verify/<학교>-<유형>.py`를 그대로 쓴다(옛 ID로 출력됨).
- 문항마다 함수 하나(`def p11(): ...`, 번호 = ID 순번). 템플릿은 `p숫자` 함수를 자동으로 모두 실행하므로 목록·개수를 고정하지 않는다.
- **정답을 하드코딩해 자기 자신과 비교하지 않는다.** 문제 설정으로부터 sympy(`integrate`, `solve`, `limit`, `summation`, `Rational`, `diff`)나 전수 열거(`itertools`)로 독립 재계산한 뒤 md의 정답과 비교. 기호 계산이 안 되면 mpmath/scipy 고정밀 수치(상대오차 1e-9).
- 다소문항은 (1)(2)(3) 각각 검산.
- 증명 소문항은 수치 반례 탐색(격자 1000점, n=1..200, 무작위 20점 등)으로 확인하고 `[증명-수치확인]` 표시.
- 가능하면 대표 오답 값도 그 실수를 재현해 계산.
- 출력: 문항마다 `<ID> PASS  <확인 내용 한 줄>` 또는 `FAIL`, 마지막 줄 `SUMMARY <학교>-<유형>-s<세트>: n/n PASS`, FAIL 있으면 `sys.exit(1)`.
- front matter `verify:` 값은 `verify/SSU-T03-s2.py::p11` 형식.
- 검산 결과가 md와 다르면 **문항을 고친다**(모범답안·채점표·정답·front matter 일관 수정). 답이 지저분하면(근호 3중, 닫힌 식 없음) 설정을 바꿔 깔끔하게.

## 7. 게이트 (전부 통과해야 verified)

- G1 sympy 검산 일치(`tools/run_verify.sh` 종료코드 0)
- G2 L 판정 규칙 충족, 세트 분포 L4×2 / L5×6 / L6×2
- G3 형식 4종 이상, 같은 형식 3회 이하
- G4 채점표 합 = 배점, 소문항 소계 = 소문항 배점(`validate.py`)
- G5 금지목록·기출·기존 DB와 비중복, 유형 안 설정 비중복
- G6 (동국·세종) 마지막 소문항이 앞 소문항 결과 사용
- G7 조건만으로 답이 유일(정의역·등호·"단," 조건 누락 없음), 교육과정·학교 범위 안(모범답안 포함)

## 8. 채점 원칙 (모범답안·채점표 작성 기준)

1. 식은 맞고 계산만 틀리면 그 단계의 1/2, 뒤 단계는 논리가 맞으면 1/2(이월 채점).
2. 답만 쓰고 과정 없음: 숭실 5점, 동국·세종 소문항 배점의 20%.
3. "보이시오"에서 결론을 가정하고 시작 → 해당 단계 0점.
4. 동국 제시문 인용 누락: 소문항당 −1.
5. 정의역·등호 조건·단위 누락: 건당 −2(숭실·동국), −5(세종).

## 9. 검토 규칙

| 단계 | 검토자에게 주는 것 | 확인 항목 | 기록 |
|---|---|---|---|
| r1 | 문항 파일 전체 + 이 지침 | 범위(모범답안 도구 포함), 학교 규격, L·형식 라벨 정확성, 금지목록·중복, 문장 모호성, G6·G7 | `reviews: {stage: r1, result: pass/fail, note}` |
| r2a·r2b | **제시문·논제만**(정답·모범답안·채점표 숨김) | 독립 풀이 → 최종 답 제출. 제작 정답과 비교는 검토자가 아니라 오케스트레이터가 한다 | `stage: r2a`/`r2b`, 불일치 시 fail + 두 답 기록 |
| verify | — | run_verify + validate | `stage: verify` |
| sample | 문항 파일 전체 | 본인이 직접 풀고 채점표대로 채점 | `stage: sample`, reviewer: human |

- `status: verified`가 되려면 r1·r2a·r2b·verify 네 단계 모두 **마지막 기록이 `result: pass`** 여야 한다(fail 후 고쳐서 다시 통과하면 새 pass 기록을 추가). 검사기가 확인한다.
- 기출(past·mock)의 r1은 "원문 PDF와 옮겨 적은 제시문·논제가 같은가"를 포함한다.

- 제작한 세션이 자기 문항을 검토하지 않는다(서브에이전트 또는 별도 세션).
- r2 두 답이 제작 정답과 다르면: 누가 맞는지 sympy로 판정 → 문항 오류면 풀이과정부터 재작성, 검토자 오류면 기록만.
- 같은 문항이 3회 연속 탈락하면 `status: retired`(ID 재사용 금지)하고 같은 유형에서 새 ID로 다시 만든다. 새 문항에 `replaces: <폐기 ID>`를 적어 세트 분포(G2·G3)가 원래 세트로 계산되게 한다.
- verify 기록은 마지막 r1·r2 기록보다 뒤여야 한다(검사기가 확인).
- 중복 확인은 `python3 tools/search.py <단어> [--school SSU --type T03]`(조사가 붙은 단어도 찾음).
